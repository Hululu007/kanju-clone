# 追剧AI iOS 0.1.19 / build 22：两个真机问题怎么修的

分支：`fix/ios-0.1.19-player-download`　版本：0.1.19（build 22）

这份是给 Ken 看的大白话说明：build 21 在手机上点出来后看到的两件事，分别是什么原因、这次怎么改的、
手机上还要确认哪些。

## 一、真机上看到的两件事

1. **点网页播放器的全屏，画面不横过来、也没铺满。** 看起来像全屏按钮没反应。
2. **下载列表看不出「哪部剧的哪一集下到哪了」。** 只有一条笼统的「正在下载 N 集」，
   没有按集排开，也没有每集自己的进度条和百分比。

## 二、根因（三处，都是代码里能指出来的）

### 全屏（两处叠在一起）

1. **iPhone 的 WKWebView 默认不让网页「元素全屏」。** 苹果这个开关（`isElementFullscreenEnabled`）默认是关的，
   网站播放器点全屏时调 `requestFullscreen()` 会被系统直接拒绝。网页那边通常就把这次失败吞掉了，
   所以真机上点全屏「什么都没发生」。
2. **没有任何人把屏幕切成横屏。** build 21 把注入层那套全屏接管全删了，原生又对所有方向一律放行；
   手机竖着拿的时候系统本来就不会自己转，于是停在竖屏。
   还有一个容易忽略的点：网页全屏是 WebKit 自己弹出来的系统控制器，它不看我们 App 页面的方向设置，
   只认 `AppDelegate` 里那个全局方向开关 —— build 21 根本没实现它。

### 下载（一处）

3. **「我的下载」只画了一条总进度行。** 进度数据其实一直在传：原生每秒好几次把「哪部剧、第几集、收了多少」
   推给网页，网页也存进了队列；但渲染那一步只取队列里的第一条（`running[0]`），其余集只写一句
   「其余 N 集排队」。所以多集一起下时，用户只能看到一条，分不清谁在跑、谁在排队，更看不到每集的百分比。

## 三、这次改了什么

- **全屏改成两态，方向由原生配合：**
  - 窗口模式（默认）：竖屏，视频还在详情页原来的位置，下面选集、简介照常；
  - 全屏模式：点站点播放器自己的全屏按钮 → 横屏铺满整块屏幕；退出（站点退出按钮或返回）→ 回竖屏原位，
    页面不重建、播放进度不跳。
  - 做法：打开 WKWebView 的元素全屏开关；注入层只在网页真正进 / 出全屏时发一条
    「进了 / 出了」消息；原生收到后把屏幕锁到横屏或切回竖屏（iOS 16+ 主动请求旋转，iOS 15 让系统重新评估）。
    `AppDelegate` 补上全局方向开关，系统全屏控制器也吃这一条。
  - 播放器仍然只有站点自己那一套，App 不加任何控件、不改页面尺寸、不写全屏样式。
- **下载列表改成一集一行：**「剧名 + 第N集」+ 进度条 + 百分比 + 已下载 / 总大小；
  排队中的集也列出来并写「排队中」。进度事件按任务 id 只更新自己那一行，每 0.25 秒一次，实时刷新。
  剧名和集号三级兜底（原生事件 → 「一键全集」记住的 → 片库 / 当前页），不会再出现没名字的行。
  下完之后那一集进片库，点一下用手机自带播放器离线播放。
- **首页顶栏回到 0.1.17 的样子：** 不再往顶栏塞 App 自己的设置按钮，站点顶栏自带的齿轮也隐藏；
  设置入口只从站点「我的」菜单进，菜单里的设置仍然打开 App 的设置面板。

## 五、真机要一条条确认的事（build 22）

1. 详情页视频在原位小窗播放，下面是选集和简介（竖屏）。
2. 点站点播放器自己的全屏 → 横屏、铺满整块屏幕，站点自己的控制栏还在。
3. 点退出全屏 / 返回 → 回到详情页原位，进度没跳、选集没丢，可以接着播。
4. 再点一次全屏，重复第 2、3 步仍然正常（不能只第一次生效）。
5. 点某集下载 → 下载页格子出现「下载中 N%」；进「我的下载」：
   每一集一行，写清「剧名 + 第N集」，有自己的进度条和百分比，数字在动。
6. 一次下 3 集：两集在跑、一集排队，三行都在，排在后面的写「排队中」。
7. 下完之后点那一集 → 能离线播放（可以开飞行模式再点）。
8. 首页顶栏没有 App 的设置齿轮；站点「我的」菜单里的设置还能打开 App 设置面板。
