# 0.1.6 真机反馈修复说明

基线：0.1.5（build 6）。本版 0.1.6 / build 7。

七条真机反馈，逐条记「现象 → 查到什么 → 改了什么 → 哪些没证明」。

---

## 1. 页面滚动迟滞、位置跳动（首页 / 详情 / 播放页多次 settle:timeout）

### 查到的东西

按「每帧要算什么」去找，找到四处真正在拖慢滚动的地方，而不是加延时：

1. **弹幕动画每帧动 `left`**。`@keyframes dm-fly{from{left:100%}to{left:-100%}}`——`left` 每帧都会触发布局和重绘，播放页上下滑时浏览器要跟弹幕抢主线程。改成 `transform:translateX`（合成层光栅化，不动布局），并给弹幕层加 `contain:layout paint`。
2. **固定顶栏/底栏的 `backdrop-filter`**。`.topbar` / `.page-head` / `.tabbar` 都是 `blur(14~16px)`，WebKit 在滚动时每帧重算模糊，长列表直接掉帧。改成等效的半透明底色（深色 `rgba(10,20,28,.97→.9)`、浅色 `rgba(255,255,255,.97→.92)`），观感几乎一致。
3. **提示行在文档流里改写文字**。`announce()` 每次都改写 `#playHint` 的文本，而它就在播放器下面、标题和选集区上面——文字一变，下面的内容整块上下跳。现在提示只走悬浮 toast，提示行本身预留 `min-height:2.6em`（两行），文案变化不再推动任何东西。这一点在浏览器里量过：把提示换成两行长文案，选集区顶部坐标位移 **0px**。
4. **横滑条的 `scroll-behavior:smooth`**。站点给日期条/分类条开了平滑滚动，任何一次 `scrollLeft` 赋值都会让整条滑过去——这既是「日期条自己漂走」，也是一次持续的合成动画。

### 顺带修掉的（同一类问题）

- 日期条停靠改成**幂等**：目标位置没变就不写 `scrollLeft`（每次写都强制一次布局）。1.6 秒内实测写入次数 **0**。
- 弹幕输入、画质增强这些控件不在滚动路径上，但一起清理了无效的 `will-change:left`。

### 没证明的

真机上的帧率没有测（Windows 上只有 Chrome 模拟）。这四处都是「按已知的浏览器渲染成本」改的：去掉了逐帧布局的属性动画、去掉了滚动期模糊、去掉了由文案引起的回流。真机上到底还剩多少迟滞，需要再取证一次。

## 2. 播放页上下滑时控制栏收起/展开导致布局跳动

根因同第 1 条第 3 点加上一个额外原因：控制栏 `#ppCtrl` 是 `position:absolute` 挂在 `#player` 里，**它本身不参与文档流**，所以「控制栏显隐」不会顶动标题。真正在动的是提示行（`#playHint`）和它下面那些元素。

现在提示行固定两行高度、提示只走 toast，播放器下方不再有内容随提示词抖动。

## 3. 竖屏右上角仍有「全屏播放」按钮

### 查到什么

那个按钮不是我们画的，也不是站点画的——设备上跑的是**已部署的老构建**，它的播放器有原生 `<video controls>`，右上角的「全屏播放」是 WebKit 自己的控件 UI。0.1.4 之后我们用自带控制栏替换了它（挂载后 `video.removeAttribute('controls')`），但只要某一帧控制栏还没挂上，原生控件就会露出来。

另外 0.1.5 的 `#iosFullBtn{display:none}` 只隐藏了元素，**无障碍名还是「全屏播放」**——自动化/读屏在全屏里仍会看到一个叫「全屏播放」的入口，这也是用户「看到还有全屏按钮」的一部分。

### 改法

- 沉浸态明确隐藏一整个清单：`#playTools`、`.pp-toolbar`、`#settingsPanel`、`#lineBar`、`.dm-input`、`#dmInputWrap`、`#pipBtn`、`#nextEpBtn`、`#iosFullBtn`、`.p-label`、`.pp-hint`、`#playHint`。
- 每个被隐藏的节点会记下原来的 `hidden` 与 `display`，**退出全屏时按原样放回**（工具条和提示行回来；设置/线路面板是进全屏时主动关掉的，退出后保持关闭，不会自己弹出来）。
- 全屏键的文案**和** `aria-label` 一起切换：进入是「退出全屏」，退出是「全屏」/「全屏播放」。
- 沉浸态按钮变大后，`退出全屏` 四个字把整条挤出屏幕（实测 387 > 367，右侧被裁）。收紧内边距、按钮 `flex:0 0 auto`、剩余宽度交给进度条，现在 367 = 367，全屏键右边缘落在控制栏内。

## 4. 外放面板没有 SenPlayer

这一条与 0.1.5 结论一致，本轮没有变：

- 分享面板里出现哪些 App，由系统按 **item 类型**筛。我们交的是 `public.url`（一条 https 地址）+ `LPLinkMetadata`，只有实现了分享扩展并声明接受 URL 的 App 才会出现。
- 设备上实际列表里没有 SenPlayer —— 这不能靠改我们的代码解决，也不能靠猜一个私有 URL scheme 解决（猜了只会变成点了没反应的按钮）。
- 已提供：分享播放地址（`public.url`）、复制播放地址（任何播放器都能粘）、下载本集后「用其他播放器打开」（把本地文件交给系统，UTI 由扩展名推断为 `public.mpeg-4`）——这是声明了视频文档类型的播放器唯一会出现的路径。
- 文案不承诺任何具体 App：面板内容由系统和已安装 App 决定。

**本轮没有新增任何第三方 scheme 适配，也没有把「支持 SenPlayer」写进任何文案。**

## 5. 下载按钮说「需登录」，点了却说「还没解析出直链」

### 查到什么

两个问题叠在一起：

1. **顺序错了**。`startDownload()` 先读地址、后判登录。观看者已经登录、这一集也正在播，却先看到「还没解析出直链」。
2. **地址来源太脆**。只读 `video.currentSrc || video.src || <source>`，站点换集或重渲染会把 `<video>` 整块换掉/清空，这时读到的就是空——于是一集刚播过的视频被判定成「没解析」。

### 改法

- **统一媒体地址来源**：`mediaState()` 按顺序看 `video.currentSrc` / `video.src` / `src` 原始属性 / `<source>` 的原始属性，只接受 `http(s)`，并且**明确排除「等于当前页面地址」的情况**（空 `src` 会被解析成页面地址，那是网页不是片源）。
- 同一集内记住最后一次真实见过的片源（`play` / `loadedmetadata` / `durationchange` 时记录），元素被重建后仍然认得出这一集。**换集就失效**：记忆里带集号，集号一变立刻丢弃，不会把上一集的地址当成这一集。
- 顺序改成先判登录、再判地址、再判分片：未登录 → 「登录后才能下载本集」；登录但真的没地址 → 「还没拿到直链：先点播放…」；HLS → 「分片线路不可下载」；加密/临时流 → 「线路不可下载」。菜单里的说明文字和点击后的提示来自**同一个函数**，不会再出现「按钮说需登录、点了说没直链」。
- 进度/取消/完成：控制栏按钮变成「下载 43%」，再点一次取消；完成提示「已下载 名字（xx MB），点「外放」可交给其他播放器」，菜单出现第四行。

### 测试

- 单测：未登录不下发（fetch=0、桥消息=0）、登录后下发、进度 43%、完成 100%、取消、失败原因、拒绝 HLS、拒绝 blob、**元素重建后仍认得出已播过的一集**、旧任务消息不串台（12 项）。
- 浏览器：四种状态下的菜单文案都按真实原因显示。

## 6. 同时显示「已登录 kenzhao11」和「游客账号」

### 查到什么

侧栏模板里，「名字」那一行按登录态渲染，而下面的**成长卡片 `.acct-name` 是写死的「游客账号」**。登录后上下一半用户名、一半游客账号，看起来像账号状态坏了。

### 改法

- 模板：`.acct-name` 改用同一个 `user` 来源。
- `refreshAccountUI()`：登录/退出后同步更新 `.acct-name`。
- App 注入层再兜一次（站点没部署前真机加载的是老页面）：监听 `kj-auth-changed`，并在点击登录/退出后补两次同步。
- 回归：`signedIn` 夹具断言 `.sb-name` 与 `.acct-name` 是同一个用户名、且不含「游客」；浏览器两侧都验过。

## 7. 选集区横滑切页（投屏/讨论/反馈）多次没反应

标签页以前**只能点**，没有任何横滑手势——所以「横滑多次 no change」不是响应慢，是根本没接。

- 站点层与注入层各自实现：横滑位移 ≥44px 且明显压过纵向（1.6 倍）才切相邻页，纵向滚动不会被误判。
- 两层同时存在时会**重复切页**（一次滑动跳两格）：注入层在自己的手势上打标记，站点层看到标记就不再处理。
- 回归：站点层、注入层两层都验了「向左滑切到下一页、目标页真的显示、纵向滑不动」。

## 8. 版本号自己漂

0.1.2→0.1.5 每版都手改 UA 字符串 `"ZhuijuAI/0.1.x iOS"`，一忘就和包版本对不上。现在 UA 从 `CFBundleShortVersionString` 取（`WebViewController.userAgent`），并加 `VersionTests`：UA 必须等于「包版本」，必须 ASCII、前缀 `ZhuijuAI/`、后缀 ` iOS`，且不能悄悄变成 `0.0.0`。
